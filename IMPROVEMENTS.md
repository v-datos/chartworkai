# Improvements & Recommendations

Lessons distilled from the projects this framework was built on and audited against, with upgrades baked in and open recommendations for operators.

## What worked well

1. **Charter-first.** The PROJECT_CHARTER got written before any code. Scope debates in week 4 were resolvable by reading the charter — that alone paid for the framework ten times over.
2. **AGENTS.md with verbatim System Prompts.** When dispatching the Marine Ecologist for a ruling, we could paste their System Prompt plus the specific ticket. Identity stayed consistent across sessions.
3. **Authority-stamped decision log.** Every ruling in `docs/decisions/` had an "Authority: Marine Ecologist" / "Orchestrator" / etc. header. Three months later we could say *who decided what* without guessing.
4. **Numbered data-quality codes (DQ-###).** DQ-005, DQ-009, DQ-013 became references in code, tests, schemas, and commit messages. Linkable IDs across the whole project.
5. **Handoff-note discipline.** Short, file-based, named the next agent. Made session-to-session continuity nearly frictionless.
6. **Strict scope separation in agent specs.** "Scope owned" / "Scope not owned" sections prevented agents from reaching into each other's work.
7. **Reproducibility non-negotiable.** `make reproduce` as the single bar for phase close. Phase 1 close-out caught three schema bugs no unit test would have found.

## Friction observed

1. **`docs/phase_plan.md` catastrophically drifted.** It was regenerated by repeatedly pasting fresh template content on top of existing content instead of editing in place. The file ballooned to **820 lines** with the same "Phase 0 / Phase 1 checklist" blocks repeated ~10 times in contradictory states. Once it was that bad, no agent could trust it — they'd read whichever copy of the section came first and act on stale information. This is the worst single failure mode we observed; the framework now hardens against it in four places: (a) a `Living-documents rule` in `agents/_shared_conventions.md` enumerating which files are update-in-place and what to do if drift is found; (b) a stop-the-presses warning header in `templates/phase_plan.template.md` with a 200-line cap and a pre-edit checklist; (c) a documentation-hygiene scan added to SOP §1 (session-start) with a one-liner shell command to detect duplicate headings; (d) a hygiene check added to the reflection prompt so drift is caught at every retro.
2. **No lightweight weekly pulse.** A `docs/weekly/` directory was defined but stayed empty. The full phase-plan update was too heavy; a one-screen `STATUS.md` was what we actually wanted.
3. **Manual "what's next?" juggling.** The operator (human) repeatedly asked "what should I dispatch next?" instead of the Orchestrator reading state and proposing. A standing `prompts/04_orchestration_turn.md` would have saved dozens of small decisions.
4. **Dispatch queue lived in chat.** "Next 5 moves" was in the phase plan but got stale. A dedicated `TASKS.md` with In Progress / Queued / Done columns survives better.
5. **Rate-limit / long-session interruptions.** An agent dispatched for Phase 2 Milestone 2 hit a rate limit and the work was lost. The framework should encourage **checkpoint artifacts** — partial outputs committed before a long run — so interruptions are recoverable.
6. **Decision files weren't always closed.** A few `OPEN_*.md` files never transitioned to the resolved state. Needs a weekly review step.
7. **No explicit "agent budget."** Some agent dispatches ballooned to 30+ tool calls. A soft budget ("target ≤10 tool calls per dispatch, escalate if more needed") would have helped stewardship.
8. **Figure regeneration was discovered late.** `make figures` existed but wasn't wired to CI until Phase 2. Should be in Phase 0 infrastructure.

## Open recommendations (not yet templatized)

These are worth trying on your next project but not yet encoded:

1. **Checkpoint commits during long agent runs.** Have long-running dispatches commit partial outputs every N minutes, so rate-limit interruptions are recoverable.
2. **Agent budget guidelines.** Add a "target budget" line to each agent spec — e.g., "typical dispatch: ≤10 tool calls; if exceeded, file a scope-of-dispatch decision."
3. **Automated charter-change-log.** A prompt that reads `docs/decisions/` diffs since last phase and drafts the `§Change log` entry.
4. **Decision-closure sweep** weekly: find `OPEN_*.md` files older than N days, prompt the authority to close or explicitly defer.
5. **Test-before-ship on every handoff.** QA's role could check any handoff claim that says "this works" — run the smoke test, post the result to the handoff comment.
6. **Single-source-of-truth enforcement.** Add a pre-commit hook that fails if `PROJECT_CHARTER.md` and `docs/phase_plan.md` disagree on current phase.
7. **Conversation-to-decision distillation.** After a long exploratory chat, run `prompts/05_decision_capture.md` to extract any implicit rulings before they're lost.
8. **Cross-project retro.** Keep a meta-log across projects of friction hit — feed it back into this framework every 6 months.

## Anti-patterns avoided (keep avoiding)

- **Letting the Orchestrator do science.** It never overrode the Marine Ecologist. This stayed true for 100+ decisions.
- **Silent schema patches.** Anomalies went to the watchlist and decision log; nothing was "fixed" invisibly.
- **Undated claims.** Every handoff, every decision, every phase-plan update had a date.

## Friction to watch for in *your* project

If you're standing this up fresh, the earliest friction points will likely be:

- Picking the right Domain Expert role-name for your project. Don't force "Marine Ecologist" — rename it to fit.
- Temptation to skip the charter because "the project is small." Even a one-page charter pays off by week 2.
- Dispatching the Orchestrator for domain calls. Resist. Route to the Domain Expert.
- Letting `docs/decisions/` become aspirational. If there's no new decision file this week and you made choices, something is undocumented.
